# Google Play policy and requirements check (October 2026)

Date: 2026-10-19. Scope: what Google's current rules mean for 1.2.0 and for the features after it. Every fact below was read on Google's official pages on 2026-10-19 by one research agent and then re-checked independently by a second agent that found each page again by search. The full quotes, verdicts and URLs are in `policy-sources/research-2026-10-19.md` and `policy-sources/verification-2026-10-19.md`.

Labels: **FACT** = quoted from an official Google page; **INTERPRETATION** = my reading for this game; **OPEN** = no official answer found.

## 1. Results that affect 1.2.0 (PR #2)

| # | Finding | Label | Action for 1.2.0 |
|---|---|---|---|
| 1 | AdMob (`play-services-ads` 19.0.0 or later) is on the Families self-certified ads SDK list. [answer/12955712] | FACT | None; 1.2.0 uses an allowed ad SDK. |
| 2 | In the Google Mobile Ads Unity plugin, `TagForChildDirectedTreatment` and `TagForUnderAgeOfConsent` are deprecated since v11.3.0 (July 2026) in favour of `RequestConfiguration.AgeRestrictedTreatment = AgeRestrictedTreatment.Child`. If both are set, "Google applies the most conservative treatment"; AdMob help calls them "functionally equivalent". [developers.google.com/admob/unity/targeting; AdMob answer/6219315; plugin release v11.3.0] | FACT | PR #2 vendors plugin 11.6.0, so the new property exists. Switch `Ads.cs` to `AgeRestrictedTreatment.Child` (keeping the old tag is harmless but deprecated). The UMP `ConsentRequestParameters.TagForUnderAgeOfConsent` is a different API and is not covered by this deprecation [INTERPRETATION]. |
| 3 | Mixed-audience apps "must not implement APIs or SDKs that are not approved for use in child-directed services unless they are used behind a neutral age screen". [answer/11043825, answer/9893335] | FACT | — |
| 4 | No official page says whether Firebase Analytics or Crashlytics is approved for child-directed services. The only related lines: Families says "For analytics, developers are encouraged to use app set ID"; the Crashlytics terms ask for COPPA compliance in general. | OPEN | **Main residual risk of 1.2.0.** Options, from safest: (a) ship Crashlytics only and drop Analytics; (b) keep both with ad-ID collection off and ad personalisation off (current PR #2), accepting the risk; (c) put Analytics behind a neutral age screen. My recommendation: (b) for 1.2.0, because analytics is needed to decide everything after it, the data contains no prohibited identifier (finding 5), and Google's own analytics is the most likely to be treated as acceptable; revisit if Play review raises it [INTERPRETATION]. Owner of PR #2 and Nikos decide. |
| 5 | Mixed-audience apps must not transmit "AAID, SIM Serial, Build Serial, BSSID, MAC, SSID, IMEI, and/or IMSI" from children or users of unknown age; they "may only transmit these identifiers from users that they know are adults"; "Transmit means to send data through the network to any off-device destination". [answer/9893335, answer/11043825] | FACT | PR #2 removes the AD_ID permission and turns off Firebase ad-ID collection; with child treatment AdMob does not transmit the AAID [AdMob answer/6219315]. Verify on the built AAB (test plan B4, B5). Firebase app-instance ID and Crashlytics installation ID are not on the prohibited list [INTERPRETATION]. |
| 6 | Families: "rewarded or opt-in ads" that interfere with play must be "closeable after 5 seconds"; ads at app launch, more than one ad per page, deceptive close buttons and "emotionally manipulative tactics" are not allowed. [answer/9893335, answer/12918983] | FACT | The rewarded continue is opt-in and shown after a loss, not at launch. Device-check that the close button appears within 5 s (add to test plan N6). No official page says how to handle the reward when a child closes early; 1.2.0 gives no reward then, which is the conservative reading [INTERPRETATION]. |
| 7 | Data safety: AdMob collects and shares IP-derived approximate location, app interactions, diagnostics and device or other IDs; Analytics and Crashlytics collect app interactions, crash logs/diagnostics and installation/app-instance IDs. [developers.google.com/admob/android/privacy/play-data-disclosure; firebase.google.com/docs/android/play-data-disclosure] | FACT | The table in `docs/SETUP-1.2.0.md` matches this. 1.2.0 cannot reuse the 1.1.0 "no data collected" answers. |
| 8 | New apps and updates must target API 36 since 2026-08-31 (extensions to 2026-11-01); existing apps need API 35 to stay available to new users; no API 37 date announced yet. [answer/11926878] | FACT | 1.1.0 and 1.2.0 target 36: compliant. |
| 9 | 16 KB page size: required for apps targeting Android 15+; updates without it are blocked from 2027-02-01 (the original 2025-11-01 date was moved). [developer.android.com/guide/practices/page-sizes] | FACT | CI already checks alignment (test plan B3). Make sure the AdMob, Firebase and UMP native libraries pass too. |

## 2. Results that shape features after 1.2.0

| # | Finding | Label | Consequence |
|---|---|---|---|
| 10 | No Families or developer-policy page mentions Play Games Services. Google's consumer help shows supervised child accounts can use PGS with parental approval and "can only use auto-generated gamer names". [support.google.com/families/answer/7106960, googleplay/answer/2954594] | OPEN | PGS is neither cleared nor forbidden. Keep it out until the audience justifies it; then achievements first, sign-in never required (competition spec step C). |
| 11 | A "social feature" lets users "share freeform content" or "communicate with large groups"; with children in the audience it needs an in-app online-safety reminder, adult controls, and adult action before children exchange personal information. [answer/9893335] | FACT | Avoid free text and player-chosen names in any feature. |
| 12 | User-generated content ("content that users contribute to an app … visible to … other users") requires terms of use, defined objectionable content, moderation and "an in-app system for reporting and blocking objectionable UGC and users". [answer/9876937] | FACT | Other players' recorded runs would probably count as UGC [INTERPRETATION]: online ghost 1v1 brings report/block and moderation duties, which conflicts with semi-passive. Offline ghosts do not. |
| 13 | Account deletion is required only "If your app allows users to create an account from within your app"; offline accounts are out of scope. [answer/13327111] | FACT | The game today needs no deletion flow. A custom backend with player identities likely would. |
| 14 | Odds disclosure applies to randomized items obtained "from a purchase". [answer/9858738] | FACT | Offline challenges and free random rewards need no disclosure; avoid paid randomness in a game with children [INTERPRETATION]. |
| 15 | Play Billing Library: new apps and updates must use version 8 or later (extensions to 2026-11-01); version 8 works until 2027-08-31. [developer.android.com/google/play/billing/deprecation-faq] | FACT | Only relevant if IAP is added; use the current Unity IAP package that bundles PBL 8+. |
| 16 | From 2026-08-26 anonymous-chat apps may not target children (Families preview). [answer/17122218] | FACT | Rules out any chat feature. |

## 3. What could not be confirmed

- Whether Firebase (or PGS) counts as "approved for use in child-directed services" (findings 4 and 10): no official list of approved non-ad SDKs exists.
- How the 5-second close rule applies inside a full rewarded video (finding 6).
- The exact Android GMA SDK version that introduced `setAgeRestrictedTreatment` (the Unity plugin version is confirmed).
